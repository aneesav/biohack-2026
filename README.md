# BioHack 2026 — scRNA-seq + Foundation Models

A self-contained pipeline for learning hands-on bioinformatics on real single-cell RNA-seq data,
ending in a real foundation-model application: using a pretrained single-cell transformer
([Geneformer](https://huggingface.co/ctheodoris/Geneformer)) to do cell type classification, and
quantitatively comparing it against the classical analysis pipeline.

Inspired by, and reusing data-ingest/QC conventions from,
[*themissingsemester*](https://themissingsemester.substack.com).

## What you'll do

1. **`notebooks/01_data_ingest_and_qc.ipynb`** — load real PBMC3k scRNA-seq data into an `AnnData`
   object, compute QC metrics, and filter out low-quality cells.
2. **`notebooks/02_classical_clustering_and_annotation.ipynb`** — normalize, find highly variable
   genes, run PCA + Leiden clustering, rank marker genes, and manually annotate cell types using
   canonical biology — the classical, pre-foundation-model workflow.
3. **`notebooks/03_geneformer_foundation_model.ipynb`** — use a pretrained single-cell foundation
   model (Geneformer-V1-10M) to embed cells, and run a real quantitative experiment: how much less
   labeled data does the foundation model need to match classical features at cell type
   classification? (Spoiler: a lot less — see the notebook for real numbers from this exact repo.)

Each notebook reads inputs and writes outputs under `data/`, so run them in order the first time.

## Setup

Requires **Python 3.10–3.12** (3.13 is too new for some pinned scientific-stack wheels at the time
of writing — see Troubleshooting below).

```bash
python3.11 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -e .
```

This single environment covers everything — classical scanpy analysis *and* the Geneformer
notebook. (Most foundation-model tutorials you'll find online tell you to use a separate
environment for the AI parts because of NumPy 1.x/2.x conflicts between scanpy and the modeling
stack; here we sidestep that by pinning NumPy `<2` everywhere, see Troubleshooting.)

Then, before running notebook 03, download the Geneformer checkpoint (~50MB, one-time):

```bash
bash scripts/setup_geneformer.sh
```

Launch Jupyter and run the notebooks in order:

```bash
jupyter lab notebooks/
```

### Hugging Face token

You generally **don't need** a Hugging Face API token for this pipeline — `Geneformer-V1-10M` is
publicly downloadable. If you hit a rate limit or want higher download throughput, set:

```bash
export HF_TOKEN=hf_your_token_here
```

before running `scripts/setup_geneformer.sh`.

## Troubleshooting

**`pip install -e .` fails trying to build `numba`/`llvmlite` from source.** Recent `llvmlite`
releases dropped prebuilt wheels for Intel Macs (x86_64) on newer Python versions, which forces a
from-source build that needs a full LLVM toolchain you probably don't have. This repo's
`pyproject.toml` pins `numba==0.61.2` / `llvmlite==0.44.0`, which still ship Intel Mac wheels — make
sure you're installing from this repo's `pyproject.toml` rather than a generic `pip install scanpy`.

**Why is NumPy pinned `<2`?** `torch` stopped publishing macOS x86_64 (Intel) wheels after version
2.2.x, and `torch==2.2.x` is only ABI-compatible with NumPy 1.x — installing NumPy 2.x alongside it
causes silent `_ARRAY_API not found` warnings and can crash on tensor/array conversion. Apple
Silicon and Linux/Windows users would get a newer `torch` automatically, which handles NumPy 2.x
fine, but pinning NumPy `<2` keeps one environment working for everyone regardless of hardware.

**Geneformer's `EmbExtractor` crashes with `Torch not compiled with CUDA enabled`.** This is a real
bug in the upstream library as of this writing — `geneformer/emb_extractor.py` hardcodes
`device="cuda"` with no CPU/MPS fallback. Notebook 03 avoids `EmbExtractor` entirely and loads the
underlying `transformers` model directly with an explicit, device-agnostic forward pass.

**Tokenizing/embedding feels stuck.** If you're running on a Mac with `mps`, batches mixing very
short and very long cells (token sequences range ~200–2000+) can make a batch pad heavily and stall.
Notebook 03 sorts cells by sequence length before batching specifically to avoid this — if you
modify the batching logic, keep (or re-add) that sort.

**Gene symbol → Ensembl ID mapping only covers ~half the genes.** Expected. Geneformer's vocabulary
covers tens of thousands of well-characterized genes; PBMC3k's full gene panel includes many
non-coding/poorly-annotated loci that were never going to map. This doesn't meaningfully hurt
results since the unmapped genes are largely uninformative anyway.

**Need a C/Fortran compiler error (igraph/leidenalg).**

```bash
xcode-select --install        # macOS
sudo apt-get install build-essential python3-dev   # Ubuntu/Debian
```

## A note on biological rigor

This is built for learning, not for publishing. A 2,700-cell single dataset with no replicates is
not enough to draw real biological conclusions — every result here is meant to teach the mechanics
of the pipeline, not to be cited.
